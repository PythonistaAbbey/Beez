# 5–7 minute presentation script

Use executive demo mode: `/en/executive` (or `/ar/executive`). Arrow keys move slides, **N** shows speaker notes, each slide has a "Live demo" button. Timings total about 6¾ minutes.

| # | Slide | Time | Say | Show |
|---|---|---|---|---|
| 1 | Precision in every delivery | 0:30 | Independent concept from Pristine Education. Built from Beez's public information; all demo data is synthetic. It complements Beez's systems. | Title slide |
| 2 | Strong operations, scattered story | 0:45 | Beez has the hard parts: refrigerated fleet, 24/7 warehouses, sensors, in-house WMS/OMS/FMS, Beez GPT. Customers meet them in separate places. | Technology page with source links |
| 3 | Customer visibility | 1:00 | One screen for map, ETA, timeline and temperature. Excursions are labelled and logged. | Control Tower → select DEMO-RX-1042 → open drawer → table view → CSV |
| 4 | Less service friction | 1:00 | Tracking answers the two questions customers call about. Issues arrive structured. | Track DEMO-FD-2210 → POD → report issue → ticket with simulated reply |
| 5 | Sensitive medical deliveries | 1:00 | Medical priority, escalation ladder with response targets, audit trail. | Alerts → acknowledge → escalate to level 2 with a note → activity log |
| 6 | Supply continuity | 1:00 | Rehearse disruption. Everything here is a labelled simulation. | Continuity → run "vehicle breakdown" → choose "swap to standby vehicle" → request backup transfer |
| 7 | Modern interface to existing systems | 0:45 | API-first, read-mostly, KSA hosting, PDPL and NCA controls, Arabic and English. | Proposal architecture section |
| 8 | Next steps | 0:45 | Two-week discovery, then a pilot on one lane or one medical customer. Indicative options in the proposal are estimates. | Quote wizard (optional) |

**If asked "is this connected to our systems?"** No. It uses synthetic data only and was built without accessing any Beez system or the client portal.
